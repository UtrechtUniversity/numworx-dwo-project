DwoServer pre-2.0 uses a MySQL database in the Dwo v1.4 format. Below are the instruction to 
upgrade and change from an v1.2 database to a Dwo v1.4 database. Knowledge about MySQL and 
Linux/Unix is assumed.

See our wiki!

===

De InnoDB vereist foreign key-constraints om een fail-over modelsafe te maken 
wegens zwakke incremental indices en om software aanpassingen te voorkomen. De 
essentiële entities in de database waar niet foutief naar mag worden verwezen 
zijn die van de school, user en schoolgroup. Bij deze kunnen rechten tussen 
scholen en gebruikers worden verwisselt. De andere entities zijn natuurlijk 
ook relevant en fouten zullen verkeerde referenties kunnen creëren, maar de 
security impact hiervan is minder en de kans op die fouten al heel erg klein.

Voor de foreign key constraints moeten een aantal aanpassingen aan dbAccess 
worden gedaan. Er is een dwo versie die de juiste delete order van objecten 
respecteert.Verder moet het database model op orde worden gebracht.

tblFromTo, tblCourseSequence en tblClass bevatten errors voor foreign key 
constraints. tblFromTo en tblCourseSequence entries moeten verwijderd kunnen worden:

====
delete from tblCourse where schoolid not in (select schoolid from tblSchool);
delete from tblCourseSequence where schoolid not in (select schoolid from tblSchool);
delete from tblFromTo where schoolfrom not in (select schoolid from tblSchool);
delete from tblFromTo where schoolto not in (select schoolid from tblSchool);
delete from tblstudentScoContext where userid not in (select userid from tbluser);
delete from tblstudentScoData where studentsco not in (select studentsco from tblstudentscocontext);

alter table tblclass modify userid int(11) NULL DEFAULT '0';
update tblclass set userid = NULL where userid not in (select userid from tbluser);

alter table tblfromto modify schoolTo int(11) NULL DEFAULT '0';
update tblfromto set schoolto = NULL where schoolto=-1;

ALTER TABLE tblsamluser ADD FOREIGN KEY (userid) REFERENCES tbluser(userid);
ALTER TABLE tblclass ADD FOREIGN KEY (userid) REFERENCES tbluser(userid) ON DELETE SET NULL;
ALTER TABLE tblstudentscocontext ADD FOREIGN KEY (userid) REFERENCES tbluser(userid);
ALTER TABLE tblclass ADD FOREIGN KEY (schoolid) REFERENCES tblschool(schoolid);
ALTER TABLE tblcourse ADD FOREIGN KEY (schoolid) REFERENCES tblschool(schoolid);
ALTER TABLE tblfromto ADD FOREIGN KEY (schoolfrom) REFERENCES tblschool(schoolid) ON DELETE CASCADE;
<!-- ALTER TABLE tblfromto ADD FOREIGN KEY (schoolto) REFERENCES tblschool(schoolid) ON DELETE CASCADE; Breekt modules delen -->
ALTER TABLE tblcoursesequence ADD FOREIGN KEY (schoolid) REFERENCES tblschool(schoolid) ON DELETE CASCADE;

ALTER TABLE tbluser ADD FOREIGN KEY (schoolgroupid) REFERENCES tblschoolgroup(schoolgroupid);

ALTER TABLE tblstudentScoData ADD FOREIGN KEY (studentsco) REFERENCES tblstudentscocontext(studentsco) ON DELETE CASCADE;
===

Om aanpassingen aan de dBAccess.java te voorkomen en uitgebreidere softwaretests 
zijn de cascade delete on toegevoegd. Als een foreign key constraint een error 
geeft kan deze gevonden worden en de betreffende referentie worden verwijdert.
